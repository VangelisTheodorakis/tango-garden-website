## What changed since the last handoff

### 1. Registration system (new)
A self-hosted, no-third-party-vendor registration flow for the beginner course:
- **Flow:** Google Form submit → Apps Script (`apps-script/Code.gs`) → Cloudflare Worker
  (`workers/registration-email/`, renders the confirmation email + `.ics` from the
  in-repo template, never sends or stores anything itself) → Apps Script sends from
  `bookings@tangogarden.de` via Gmail.
- **Why this shape:** keeps email sending on Google Workspace (no new GDPR sub-processor)
  while still template-driving the content from the codebase (`src/lib/email.js`,
  `src/data/courses.js`).
- **Calendar:** `.ics` feed hosted at `/calendar/regular-classes.ics`, generated from the
  same `public/assets/data/regular-classes.json` the pathway cards already read — one
  source of truth for dates.
- **Deployed:** Worker is live (`https://tango-garden-registration.vangelis-theodorakis.workers.dev`),
  secret is set via `wrangler secret put` (never in source), auth confirmed (401 on
  missing/wrong secret, 405 on GET).
- **Not yet live:** the Google Form itself. See "Open item" below.

### 2. Class pages consolidated (major restructure)
The old one-page-per-SKU structure (8 near-duplicate product pages: general admission,
student/under-28, 1-class, 4-class, full-course...) was replaced with **one page per
class**, each with a single combined pricing/perks table:
- `/pages/enter-the-garden`, `/pages/beginner-course`, `/pages/garden-practica` — all
  rendered from one shared component (`src/components/ClassPage.astro`) driven by
  `src/data/classPages.js`.
- Old SKU pages are `hidden: true` in `products.js` (still reachable by direct URL,
  noindexed) and 301 to the new pages via `public/_redirects`.
- Pricing tiers (General / Reduced) use a pill-shaped toggle instead of a cramped
  side-by-side column.
- `/collections/all` ("Classes & Passes") is now 3 cards, one per class, each linking to
  its consolidated page.

### 3. Real photography
Enter the Garden and the beginner course both got real event photos (hero + gallery),
replacing the shared placeholder. Garden Practica still uses the shared placeholder —
**no photos have been provided for it yet.**

### 4. Start Here page removed
It duplicated content that already lived elsewhere (pathway cards on the homepage and
`/collections/all`, FAQ on each class page). Its two unique sections ("This Space Is For
You If" and the "you're exactly where you should be" reassurance) moved to
`/pages/the-garden`. Old URL 301s there.

### 5. Navigation bug fixes
- **Mobile:** tapping "The Garden" or "Classes" in the burger menu used to only expand the
  submenu (native `<details>`/`<summary>`) instead of navigating, unlike desktop where the
  same label is a real link. Fixed — the label now navigates, a separate chevron button
  expands the submenu.
- **Desktop:** the dropdown had a 6px gap between the nav link and the submenu with pure
  CSS `:hover` and no transition delay, so crossing that gap (especially on a slow or
  non-vertical mouse path) broke hover and hid the menu before the cursor arrived. Fixed
  by making the dropdown sit flush against the link (visual spacing moved into padding).

### 6. Footer expanded
Was missing Classes & Passes and the three class pages, and the WhatsApp icon (only
Facebook/Instagram were there). All added; grid updated from 3 to 4 columns on desktop.

### 7. Contact page map now auto-embeds — a deliberate rule override
**This is worth flagging explicitly.** The project's non-negotiable GDPR rule was "the
map is click-to-load, never auto-embedded." The owner explicitly asked to change this on
2026-08-08, and it's now documented as an accepted, scoped exception in `CLAUDE.md`
(item 1 under "Non-negotiable project rules") — the map on `/pages/contact` sends visitor
IPs to Google on page load, same as any embedded Google Map would. Do not extend this
exception to any other embed without asking first.

### 8. Sitewide em dash cleanup
Every em dash in user-facing copy (titles, body text, FAQ, legal pages, the old per-SKU
product catalogue) was replaced with commas/colons, per owner preference. Page `<title>`
tags now use `|` instead of `—` as the site-name separator.

### 9. Security audit + dead-code cleanup (today, 2026-08-08)
Full write-up in commit `e1d4de2`. Summary:
- **Security:** no critical/high findings. Fixed the contact map iframe's referrer policy
  (was looser than the site's global header) and cleared the one fixable `npm audit`
  advisory (`undici`, non-breaking). Remaining `npm audit` findings are entirely inside
  `@lhci/cli`'s own dev tooling — never shipped to `dist/` or the deployed Worker, left
  as-is rather than force a breaking CI-tool upgrade for a devDependency with no
  production exposure.
- **Dead code removed:** 4 one-off migration scripts whose job was done
  (`tools/port-pages.mjs`, `compare-legacy.mjs`, `extract-products.mjs`,
  `fix-course-schema.mjs`), 7 dead CSS rules + a duplicate `.page-hero` declaration, a
  stale `/pages/start-here` link in `docs/registration-form-spec.md`, and a full rewrite
  of `README.md` (was still describing GitHub Pages hosting and the pre-consolidation
  page structure).
- **`legacy/` directory** (the pre-Astro Shopify HTML export, ~640KB): asked the owner
  whether to keep or remove now that nothing in the live build references it — **decision:
  keep**, as historical reference.
- **Bonus bug fix:** the dead-CSS pass surfaced a real issue — the two "Our Story" photos
  on `/pages/the-garden` had zero gap between them because the CSS selector
  (`img + img`) never actually matched (a caption `<p>` always sits between the two
  images). Fixed.

## Open item: the registration Google Form is not live yet

Code is done and tested. What's left is manual setup on the owner's Google account — full
checklist in [`docs/registration-todo.md`](../../docs/registration-todo.md), copy spec in
[`docs/registration-form-spec.md`](../../docs/registration-form-spec.md). Short version:

1. **Form fix needed:** switch off "Collect email addresses: Verified" (currently requires
   a Google sign-in to even respond, which excludes anyone without a Google account) and
   add a plain Email question instead.
2. Paste `apps-script/Code.gs` into the form's Script editor, set `WORKER_URL` and
   `SHARED_SECRET` script properties, wire the `onFormSubmit` trigger, authorize scopes.
3. Confirm `bookings@tangogarden.de` is a verified "Send mail as" alias on the account
   running the script.
4. Test end-to-end (submit as yourself, confirm the email + `.ics` arrive, confirm it
   works from a signed-out/incognito browser).
5. **Publish the form** (currently sits as "Not Published" in the form editor).

None of this touches the deployed site — it's entirely Google Form/Apps Script
configuration in the owner's Google account.

## Non-negotiable project rules (current, see `CLAUDE.md` for full detail)

1. **Zero third-party requests on page load (GDPR), with one accepted exception** — the
   contact page's Google Map now auto-embeds (see item 7 above). Everything else still
   holds: self-hosted fonts/images, no external scripts/stylesheets, no analytics.
2. **Deploy = `git push` to `main`.** No separate deploy step; never `wrangler deploy`
   directly (a hook blocks it).
3. **Products mirror the live Shopify store** — `src/data/products.js` variant IDs must
   stay in sync. Purchase controls are still hidden (`showPurchaseControls` in
   `src/data/site.js`); buy buttons open a Shopify cart permalink.
4. **Mobile-first.** Verify 320/375px before desktop on any layout change.
5. **No payment-provider branding** anywhere visible.

## How to resume this project

1. Read `CLAUDE.md` first — it's the authoritative project reference (rules, architecture,
   commands, deploy flow, owner working preferences).
2. Check auto-memory (`MEMORY.md`) for durable facts (hosting, DNS, Shopify parity,
   mobile-first, Cologne landscape context).
3. Verify live: `curl -s https://tangogarden.de/ | head -5` should return the current
   homepage HTML.
4. Run `npm run dev` (port 3001) and `npm test` before starting any change.

### Key commands
```bash
npm run dev         # localhost:3001
npm run build        # dist/
npm test              # unit + build-output tests
npm run test:e2e     # Playwright, desktop + mobile
npm run check         # astro check (6 pre-existing type warnings in [handle].astro-family
                       # pages, unrelated to any change in this session — TS narrowing on
                       # a `.find()` result, not a real bug)
npm run dead-css      # report CSS with no match in the built output
```

### Deployment
```bash
git add <files>
git commit -m "<message>"
git push origin main    # Cloudflare auto-builds and deploys, ~45-60s propagation
```
