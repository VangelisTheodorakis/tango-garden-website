## What changed since the last handoff

### 1. Google Analytics 4: a deliberate GDPR rule change
**This overrides project rule 1.** The owner explicitly chose GA4 **without a consent
banner** ("small school, <5k €/year, ignore GDPR for now").
- **Property:** `properties/550087499` (Measurement ID `G-35BD84HHPR`, stored in
  `src/data/site.js` as `gaMeasurementId`).
  - Owner account: vangelis.theodorakis@tangogarden.de.
  - Account data-sharing toggles: all off except Technical support.
- **Privacy policy:** section 10 in `privacy-policy.astro` and its German mirror discloses
  GA4, with the legal basis Art. 6(1)(f).
- **CSP** (`public/_headers`): `googletagmanager.com` is allowed in `script-src` and
  `img-src`, and the `*.google-analytics.com` / `*.analytics.google.com` hosts in
  `connect-src` and `img-src`. Everything else is still `'self'`.
- **Loader** (`src/layouts/BaseLayout.astro`):
  - gtag.js is injected **only on `tangogarden.de` / `www`**, and only after window load
    plus idle.
  - The `gtag()` stub must push `arguments`, not a rest-param array. This was bug 2 below.
  - `content_group` goes on the `config` call.
- **Custom events:**
  - `faq_expand` (param `faq_question`), sent from class pages and the contact page.
  - `pricing_tier_toggle` (param `tier`).
  - German FAQ buttons carry `data-faq-key` with the English question, so both languages
    report under one value.
- **GA admin config (done by the owner):**
  - `register_click` is the **Key Event**. It is derived from `click` where
    `link_domain contains forms.gle`.
  - `whatsapp_click` is a regular event. It is derived from `click` where `wa.me`.
  - Both have "Copy parameters from the source event" ticked.
  - `FAQ question` is registered as an event-scoped custom dimension.
  - Enhanced measurement: page views, scrolls, outbound clicks on; site search, video,
    downloads, forms off.
- **Bugs found and fixed along the way. Remember these:**
  1. CSP `img-src` blocked GA's image-beacon hits, so zero data arrived.
  2. The `gtag()` stub pushed a real Array, and gtag.js silently ignored every command.
  3. Localhost, Playwright and Lighthouse runs (including CI) reported to the live
     property. That was 1,602 of 2,811 sessions before 26 Sep. **For data before
     26 Sep, filter `hostName = tangogarden.de`.**
  4. `gtag('set', 'content_group', …)` never registered. It is now sent on `config`.

### 2. German version under `/de` (launched 2026-09-26, commit `40dfc9d`)
- **URLs:** the German URL is `'/de' + englishPath`, with the same slugs. English stays
  the default at the existing URLs. The switcher (EN | DE) sits in the header on mobile
  and desktop. It is a plain link: no auto-redirect, no cookies.
- **Scope:** every page is translated, "du" form throughout. Only the 12 hidden, noindexed
  product pages stay English-only.
- **Source of truth:** `src/i18n/index.js` `translatedPaths`. It drives:
  - `localizePath`, `switchPath` and `alternatesFor`
  - the hreflang tags (`en`, `de`, `x-default`)
  - the German build tests

  Add a path there when a new page gets a German twin.
- **Copy location:**
  - Shared chrome (nav, footer, switcher): `src/i18n/ui.js`.
  - Nav labels are keyed by the English href, so `src/data/nav.js` stays English-only.
  - Component copy lives in each component, in `copy` / `text` objects keyed by locale.
  - Class pages: `src/data/classPages.de.js` holds only the German words, merged onto
    the English entry by `getClassPage()`. Prices, handles, feeds and the register URL
    stay single-source.
  - Rhythm trainer: `src/data/rhythmExercises.de.js`, an overlay keyed by exercise id
    and glossary term.
- **Shared styles:** the About and Contact pages' styles moved to
  `src/styles/the-garden.css` and `src/styles/contact.css`. The contact FAQ script moved
  to `src/scripts/contact-faq.ts`. Both languages share them.
- **Date feeds** (`public/assets/data/*.json`): `label_de` and `emptyMessage_de` were
  added alongside the English fields. **When the owner edits `label`, `label_de` needs
  the same update.** `next-event.js` formats German dates as `Mi., 29.07.2026`.
- **Teaching language:** classes are taught in English, with individual feedback in
  German, Greek or Russian. The German class pages say so near the top. The register
  form is English-only (owner decision), and the German pages say so.
- **Map:** the auto-embedded Google Map exception now also covers `/de/pages/contact`
  (owner decision, 2026-09-26). No other embeds.
- **Legal:** the German privacy policy, AGB and refund policy are AI translations of the
  English texts. **They need a legal check.** There is no "which language prevails"
  clause. Legal pages are noindex in both languages, and the sitemap filter covers the
  `/de` versions.
- **Layout:** German legal pages hyphenate (`html[lang="de"] .legal-page`), because
  compounds like "Geschäftsbedingungen" scrolled sideways at 320px.

## Gotchas learned this period

- **`npm run lhci` uploads reports to a public server** (`temporary-public-storage` in
  `lighthouserc.json`). To check locally without uploading, run
  `npx lhci collect --url=…` followed by `npx lhci assert`.
- **Test runs reported to GA before the host gate existed.** If a new analytics tag is
  ever added, gate it by hostname too.
- **The Search Console "Page indexing" report lags by days.** The URL Inspection API
  (`url_inspection.py` in the notfair skill, or the UI) shows the current state.
- **GA access for Claude is read-only through a service account**, because Google blocks
  `gcloud` from requesting the Analytics scope on personal accounts:
  `gcloud auth print-access-token --impersonate-service-account=ga-reader@tango-garden-seo.iam.gserviceaccount.com --scopes=https://www.googleapis.com/auth/analytics.readonly`.
  Search Console uses the normal gcloud ADC login (project `tango-garden-seo`).
- **PowerShell splits comma lists in arguments.** Quote values like
  `--scopes="a,b,c"`.
- **The short `forms.gle` link can't carry pre-filled answers.** Switching the register
  button to a `docs.google.com/forms/...` link would also break the `register_click` Key
  Event, which matches `forms.gle`.
- **Two Google accounts are in play.** `gcloud` and Cloud run as
  van.theodorakis@gmail.com. GA4, and Workspace email, are owned by
  vangelis.theodorakis@tangogarden.de.

## Non-negotiable project rules (current state)

1. **Minimal third-party requests.** The accepted exceptions, each an explicit owner
   decision:
   - GA4 on every page, no consent banner (2026-08-16)
   - the auto-embedded Google Map on `/pages/contact` (2026-08-08) and on
     `/de/pages/contact` (2026-09-26)

   Everything else is self-hosted. Ask before adding any other external request.
2. **Deploy = `git push` to `main`.** Never run `wrangler deploy` directly; a hook blocks
   it.
3. **Products mirror the live Shopify store** (`src/data/products.js`). Purchase controls
   are still hidden.
4. **Mobile-first.** Verify 320/375px before desktop. The e2e layout suite includes every
   German page.
5. **No payment-provider branding.** Plain-text "cash or PayPal" is allowed. Logos and
   badges are not.

## How to resume this project

1. Read `CLAUDE.md` first. It is the authoritative project reference and is current as of
   this handoff.
2. Read this handoff and [`docs/marketing-analytics-todo.md`](../../docs/marketing-analytics-todo.md).
3. Check auto-memory (`MEMORY.md`). It now also covers the bilingual decisions,
   marketing channels, GA access and the baseline numbers.
4. Run `npm run dev` (port 3001) and `npm test` before starting a change.

### Key commands
```bash
npm run dev          # localhost:3001 (GA does not load on localhost, by design)
npm run build        # dist/, 40 pages
npm test             # unit + build-output tests, including the hreflang/language suite
npm run test:e2e     # Playwright, desktop + mobile
npm run check        # astro check, 0 errors expected
```

### Deployment
```bash
git add <files>
git commit -m "<message>"
git push origin main    # Cloudflare auto-builds and deploys, ~45–60s
```
